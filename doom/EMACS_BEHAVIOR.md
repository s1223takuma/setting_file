# 現在の Emacs 動作表

この表は、このディレクトリの `init.el`、`config.el`、`custom.el`、その他の設定ファイルと、この環境に入っているDoom・pdf-toolsの定義から読み取れる動作をまとめたもの。PDFのキーは実行中のEmacsでも確認した。それ以外の大部分は設定の読み取り結果で、すべてのキーを実機操作で試したわけではない。`SPC` は Doom/Evil の leader キー、`:名前` は Evil の Ex コマンドを表す。`C` は Ctrl、`M` は Meta を表し、`C-x C-s` は Ctrl+x の後に Ctrl+s を押す。

| 表記 | 押し方 |
| --- | --- |
| `C-x` | Ctrlを押しながらx |
| `M-x` | Metaを押しながらx。macOSでの実際の修飾キーはEmacsのキー設定による |
| `SPC p p` | NormalモードでSpace、p、pを順番に押す |
| `RET` / `TAB` | Return／Tab |
| `N` / `P` | Shiftを使った大文字のN／P。小文字の `n` / `p` とは別 |
| `C-c C-c` | Ctrl+c、次にCtrl+c。最初の操作を入力してから次を入力する |
| `:Py` | EvilのEx入力を開き、`Py` と入力してReturn |

## まず覚える単位

| 名前 | 意味 | 例 |
| --- | --- | --- |
| バッファ | Emacsが開いている作業内容。ファイル、PDF、ターミナル、検索結果などが入る | 同じファイルを別ウィンドウに表示してもバッファは1つ |
| ウィンドウ | フレーム内でバッファを表示する区画 | `C-x 2` で上下に2区画へ分割 |
| フレーム | OS上のEmacsのウィンドウ | `C-x 5 2` で新しいフレーム |
| workspace | Doomの作業領域。表示・切り替え対象のバッファをまとめる | `SPC TAB n` で新規作成 |
| モード | バッファの種類に合わせて機能やキーを切り替える仕組み | PDFなら `pdf-view-mode`、Orgなら `org-mode` |
| Evilの状態 | Normal、Insert、Visualなど、キーの意味を切り替える状態 | Normalの `j` は移動、Insertの `j` は文字入力 |

同じ `n` でも、PDFの Normal モードでは「次の検索結果」、ほかのモードでは別の操作になることがある。以下のキーは、表に書かれたモード・状態で使う。

### 操作に迷ったとき

| やりたいこと | 操作 |
| --- | --- |
| 今押したいキーが何をするか調べる | `C-h k`、続けて調べたいキーを押す |
| 今のバッファで使えるキーを一覧にする | `C-h b` |
| 現在のメジャーモードを確認する | `C-h m` または `M-x describe-mode` |
| 関数名から説明を調べる | `C-h f` |
| 設定変数を調べる | `C-h v` |
| キーが分からないコマンドを使う | `M-x` でコマンド名を入力 |
| 長い操作を中止する | `C-g` |
| Doomの次のキー候補を見る | `SPC` または `SPC p` などを押して少し待つ |

Normalモードで `SPC` の候補が出ないときは、現在のEvil状態も確認する。Insert状態でleaderを使うときは、このDoom設定では `M-SPC` が代替キーになっている。

## PDF の読み方と検索

現在開いているPDFバッファが `pdf-view-mode` であることを実行中のEmacsで確認した。以下のキーも、そのPDFバッファの Normal モードで実際の割り当て先を確認している。PDFを開いてから `M-x describe-mode` でモード名を確認できる。

### 検索で次の一致箇所へ行く

1. PDFの画面で `/` を押す。
2. 検索語を入力する。入力中に次の一致箇所へ進みたいなら `C-s`、前に戻るなら `C-r`。
3. `RET` で検索を確定する。
4. **次の一致箇所は `n`、前の一致箇所は `N`。**

`C-s` から検索を始める方法もある。検索中は `C-s` で次、`C-r` で前。`RET` で検索を終えた後は `n` / `N` を使う。PDFの Normal モードで単独の `C-r` はこの環境では Evil の redo に割り当てられている。検索を取り消して元の位置に戻すときは検索中に `C-g` を押す。

| キー | PDF表示中の動作 |
| --- | --- |
| `/` / `?` | 前方／後方へ検索を開始 |
| `C-s` | 前方へ検索を開始。検索中にもう一度押すと次の一致箇所 |
| 検索中の `C-r` | 前の一致箇所へ戻る |
| `RET` | 検索語を確定して検索入力を終える |
| `n` / `N` | 確定済みの検索を次／前へ繰り返す |
| `M-s o` | PDF内の一致箇所を一覧表示する `pdf-occur` |
| `j` / `k` | 画面を下／上へ移動。端まで行くと次／前のページへ |
| `C-f` / `C-b` | 画面を下／上へ大きくスクロール。端まで行くと次／前のページへ |
| `M-x pdf-view-next-page-command` / `M-x pdf-view-previous-page-command` | 次／前のページへ直接移動 |
| `gg` / `G` | 最初／最後のページへ。数字を付けた `G` は指定ページへ |
| `W` / `H` / `P` | ページを幅／高さ／全体に合わせる |
| `zi` / `zo` / `z0` | 拡大／縮小／倍率をリセット |
| `o` | PDFの目次を開く。目次があるPDFで使用 |
| `f` / `F` | PDF内のリンクを選択／リンクの操作を実行 |
| `q` / `Q` | PDFのウィンドウを閉じる／PDFバッファを終了する |

pdf-tools単体のキー表と、このDoom/Evil環境でのキーは一部違う。特にここでは `n` / `N` は検索結果の移動に使う。PDFの表示倍率は初期状態でページ全体に合わせる設定。LaTeXのPDFプレビューもこの `pdf-view-mode` で開く。検索しても何も見つからないときは、PDFに検索可能な文字データが含まれているかも確認する。

### PDFへの注釈と表示変更

次のキーも現在開いているPDFバッファで割り当て先を確認した。注釈を書き込めるかはPDFファイルとpdf-toolsの対応状況による。

| キー | 動作 |
| --- | --- |
| `C-c C-a h` | 選択した文字にハイライト注釈を追加 |
| `C-c C-a t` | テキスト注釈を追加 |
| `C-c C-a l` | 注釈の一覧を開く |
| `C-c C-a D` | 選択中の注釈を削除 |
| `zd` | 暗い表示へ切り替える |
| `zm` | PDFのmidnight表示を切り替える |

ハイライトはPDF上の文字をマウスで選択してから `C-c C-a h` を使う。PDFが画像だけで文字を選択できない場合、文字検索とハイライト注釈は期待どおりに使えない。

## Doom 標準のよく使う leader キー

この表は、この環境に入っているDoomの標準キーバインド定義から確認したもの。`SPC` は Evil の Normal モードなどで使用する。Insert モードなどでは代替leaderの `M-SPC` を使う設定になっている。

| `SPC f f` | ファイルを開く |
| `SPC f s` | ファイルを保存 |
| `SPC f r` | 最近開いたファイルを選ぶ |
| `SPC b b` | 現在のworkspaceにあるバッファを切り替える |
| `SPC b B` | 全体からバッファを切り替える |
| `SPC b d` | バッファを閉じる。この設定では自作キーが優先 |
| `SPC p p` | 別のプロジェクトへ切り替える |
| `SPC p f` | 現在のプロジェクト内でファイルを探す |
| `SPC p b` | プロジェクト内のバッファへ切り替える |
| `SPC p .` | プロジェクトのディレクトリを閲覧 |
| `SPC p a` | プロジェクトを既知の一覧へ追加 |
| `SPC p d` | 既知の一覧からプロジェクトを削除 |
| `SPC p i` | プロジェクトのキャッシュを無効化 |
| `SPC s b` | 現在のバッファ内を検索 |
| `SPC s p` | 現在のプロジェクト内を検索 |
| `SPC s d` | 現在のディレクトリ内を検索 |
| `SPC TAB .` | workspaceを選んで切り替える |
| `SPC TAB n` / `SPC TAB N` | 新しいworkspaceを作る／名前を付けて作る |
| `SPC TAB [` / `SPC TAB ]` | 前／次のworkspaceへ移動 |
| `SPC TAB r` | workspaceの名前を変更 |
| `SPC TAB d` | 現在のworkspaceを削除 |
| `SPC w` | ウィンドウ操作のメニュー |
| `SPC h` | ヘルプ操作のメニュー |
| `SPC n` | Orgやメモの操作のメニュー |

`SPC p` はコマンド単体ではなく、プロジェクト操作の入口となるキー。たとえばプロジェクトを切り替える操作は `SPC p p`。`SPC` を押した後にしばらく待つと、Which Key が続きの候補を表示する。

### 検索する場所による使い分け

| 場面 | 操作 | 結果の出方 |
| --- | --- | --- |
| PDF内の文字を探す | `/` → 検索語 → `RET` → `n` / `N` | PDF内の一致箇所へ順に移動 |
| 普通のテキストバッファを検索 | `SPC s b` | 現在のバッファ内を候補から選ぶ |
| プロジェクト内のファイルを横断検索 | `SPC s p` | プロジェクト内の一致箇所を候補から選ぶ |
| 現在のディレクトリ以下を横断検索 | `SPC s d` | ディレクトリ内の一致箇所を候補から選ぶ |
| PDFの一致箇所を一覧にする | `M-s o` | PDFの検索結果一覧を表示 |

Org本文では、この設定が `C-s` を「予定日の設定」に割り当てている。Org本文で検索したいときは Normal モードの `/` または `SPC s b` を使うと分かりやすい。PDF内では `C-s` が検索を開始する。

### 候補一覧の操作：Vertico と Corfu

`M-x`、ファイル選択、バッファ選択など、画面下部に入力欄が出る場面ではVerticoを使う。編集中にカーソル付近へ補完候補が出る場面ではCorfuを使う。両者は表示場所と役割が違う。

| 場面 | キー | 動作 |
| --- | --- | --- |
| Verticoの候補一覧 | 文字を入力 | 候補を絞り込む。Orderlessが有効 |
| Verticoの候補一覧 | `C-j` / `C-k` | 次／前の候補へ移動 |
| Verticoの候補一覧 | `RET` | 選択中の候補を確定 |
| Verticoの候補一覧 | `TAB` | 選択中の候補を入力欄へ挿入し、さらに入力を続ける |
| Verticoの候補一覧 | `M-RET` | 候補の選択ではなく、入力した文字列をそのまま確定 |
| ファイル選択中のVertico | `C-h` | 親ディレクトリへ移動 |
| ファイル選択中のVertico | `C-l` | ディレクトリへ入る／候補をプレビュー |
| Corfuのポップアップ | `↓` / `↑` または `M-n` / `M-p` | 次／前の補完候補へ移動 |
| Corfuのポップアップ | `RET` | 選択中の候補を挿入 |
| Corfuのポップアップ | `TAB` | 補完を進める |
| Corfuのポップアップ | `C-g` | 候補表示を閉じる |

この設定のCorfuは、1文字入力後に0.1秒待つと候補を自動表示する。候補ポップアップが出ている間は、そのポップアップのキーマップが通常のキーより優先される場合がある。

### ファイルを開いたとき・保存したとき

| 対象 | 操作 | この設定で自動的に起きること |
| --- | --- | --- |
| Python | `.py` を開く | PythonモードとLSP・Pyrightの設定を使う |
| Python | 保存する | Ruffが見つかれば保存前に整形。なければ整形対応のLSPで整形。失敗しても保存処理は続く |
| LaTeX | `.tex` を開く | 同名のPDFがあれば右側に表示。なければ `latexmk` で生成を要求し、成功したら表示 |
| LaTeX | `.tex` を保存する | `latexmk -lualatex` を非同期実行。続けて保存されたときは実行要求をまとめる。成功すれば開いているPDFを更新 |
| Org | Agenda対象のOrgファイルを保存する | ダッシュボードのTodayとカテゴリーのキャッシュを消し、表示中なら再描画 |
| Org | Agendaを開く | 対象ファイルのOrg構文キャッシュをリセットしてからAgendaを開く |
| Markdown | `.md` を開く・保存する | Markdown編集機能を使う。PDFへの自動変換はまだ設定されていない |

LaTeXの手動コンパイル用コマンドは `M-x my/latex-compile`。PDF生成には外部コマンド `latexmk` とTeX環境が必要で、リモートファイルの自動コンパイルはスキップする。Python整形には `ruff` または整形可能なLSPサーバーが必要。これらの外部ツールの有無で実際の動作は変わる。

### OrgでPythonのコードブロックを使う

1. Orgファイルを開き、挿入したい行へ移動する。
2. Normalモードで `SPC i p` を押す。`#+begin_src python` と `#+end_src` の間にカーソルが来る。
3. Pythonコードを書く。Orgのソースブロックを実行するときは、ブロック上で `C-c C-c` を使う。実行できる言語や実行結果の形式は Org Babel の設定と環境に依存する。

`SPC i p` はグローバルのleaderに登録されているが、関数の中でOrgモードを確認している。Markdownなどで実行すると「Orgモードで実行してください」と表示して挿入しない。

### Evilの基本編集と、この設定での注意点

ここでは、普通のテキストバッファをNormalモードで操作する場合を想定する。PDF、Dired、Magit、vtermなどでは同じ文字キーが専用操作に変わる。

| キー | 動作 |
| --- | --- |
| `h` / `j` / `k` / `l` | 左／下／上／右へ移動 |
| `w` / `b` / `e` | 次の単語の先頭／前の単語の先頭／単語の末尾へ移動 |
| `0` / `$` | 行頭／行末へ移動 |
| `gg` / `G` | ファイルの先頭／末尾へ移動 |
| `i` / `a` | カーソル位置／カーソルの後ろから入力を始める |
| `o` / `O` | 下／上に新しい行を作って入力を始める |
| `Esc` または `jk` | InsertモードからNormalモードへ戻る |
| `v` / `V` | 文字単位／行単位で選択を始める |
| `y` | 選択した範囲をコピーする。通常は移動キーと組み合わせる |
| `yy` | 現在行をコピー |
| `p` / `P` | カーソルの後ろ／前に貼り付け |
| `u` / `C-r` | 編集を元に戻す／やり直す |
| `/` / `?` | 前方／後方を検索 |
| `n` / `N` | 検索を同じ方向／逆方向へ繰り返す |
| `:` または `;` | Exコマンドを入力。この設定では `;` もExへ割り当て |

この設定では `x` が「コピー用レジスタを変えずに1文字削除」に変更されている。また、`dw` は通常のVimでよく見る「次の単語を削除」ではなく、**前の単語へ戻りながら削除**する自作コマンド。`dd` は行全体を削除し、`Y` はカーソルから行末までコピーする。現在の選択操作は上の「Evil の独自キー操作」表も参照。

### ウィンドウ、バッファ、workspaceを実際に使う

1. `C-x 3` で左右に分割する。同じバッファを2か所に表示することもできる。
2. `C-x o` で反対側へ移動し、`SPC f f` で別のファイルを開く。
3. `C-x 0` で今いる区画だけ閉じる。表示していたバッファは残る。
4. `SPC b b` で現在のworkspace内のバッファを選ぶ。全体から選ぶ場合は `SPC b B`。
5. 別の作業を分けたいときは `SPC TAB N` で名前付きworkspaceを作る。`SPC TAB .` で切り替える。

バッファを消す操作は `C-x k` または `SPC b d`。ウィンドウだけを閉じる `C-x 0` と区別する。フレームを増やす場合は `C-x 5 2`。DoomのworkspaceとEmacsのtab-barタブも別の仕組みで、`g n` はこの設定ではtab-barの新規タブを作る。

## Diredでファイルを扱う

`C-x d` または `SPC f d` からディレクトリを開く。今開いているファイルの場所へ行くなら `SPC o -` も使える。以下は開いているDiredバッファで実際の割り当てを確認したNormalモードのキー。

| キー | 動作 |
| --- | --- |
| `j` / `k` | ファイル一覧を下／上へ移動 |
| `RET` | カーソル位置のファイル・ディレクトリを開く |
| `^` または `-` | 親ディレクトリへ移動 |
| `m` | ファイルにマークを付ける |
| `u` | カーソル位置のマークを外す |
| `U` | すべてのマークを外す |
| `C` | マークしたファイルをコピー。マークがなければカーソル位置のファイルを対象にする |
| `R` | マークしたファイルの名前変更・移動 |

マークは複数ファイルをまとめて操作するときに使う。削除は `d` だけでは実行されず、`x` で確認してから実行する。`D` は直接削除操作へ進むため、対象をよく確認する。

## MagitでGitを扱う

`SPC g g` で現在のリポジトリのMagit画面を開く。状態画面では「未追跡」「未ステージ」「ステージ済み」などの欄を移動しながら操作する。以下はこの環境のMagitとEvil Collectionのキー定義から確認したもの。

| キー | Magit画面での動作 |
| --- | --- |
| `j` / `k` | 行を下／上へ移動 |
| `TAB` | 現在の項目を展開・折りたたむ |

## vtermでシェルを使う

| 操作 | キー・方法 |
| --- | --- |
| vtermを開く・表示ウィンドウを閉じる | `SPC o t`。この設定の自作トグル |
| Doom標準のvtermポップアップを開く | ダッシュボードの `Terminal` ボタン。`SPC o t` は自作のトグル操作 |
| 現在の場所でvtermを開く | `SPC o T` |
| Normalモードからシェル入力へ戻る | vterm上で `i` |
| 実行中のシェルコマンドを中断 | vterm上で `C-c C-c`。vtermへCtrl+Cを送る |
| vtermの文字をコピーしやすい状態にする | `C-c C-t` でcopy modeを切り替える |
| カンマを入力する | Insertモードで `,`。通常の編集バッファと違い、空白を追加せずカンマだけを送る |

vtermのNormalモードで `,` を押すとEvilの検索移動コマンドになる。シェルへカンマを入力するには `i` でInsertモードへ入る。Insertモード中の多くのCtrlキーはEmacsではなくシェルへ送られる。Emacsのキーを使いたいときはNormalモードに戻る。`SPC o t` はウィンドウの表示を切り替える操作で、シェルのプロセスを終了する操作ではない。
